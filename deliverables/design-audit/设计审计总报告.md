## 阶段一：站酷设计参考提炼

四个参考页全部指向「B 端 / 企业级 SaaS」品类，设计语言高度一致，可归纳为「**单一主色 + 中性灰 + 极少量功能色**」的克制风格，作为本项目改进的对标基准。

### 1.1 三套作品页（图片为主）

| 页面 | 设计师 | 品类 | 可见设计语言 |
|------|--------|------|--------------|
| SaaS 产品「医器云」系统 | Andy丶子陌 | 医疗器械行业 SaaS | 专业蓝/青冷色系、信息密度高、表格+表单密集型、克制状态色 |
| B 端 SaaS 系统页面全流程设计案例 | JTooo | 通用 B 端全流程 | 登录→仪表盘→列表→表单→详情 全链路；统一圆角/主色/弱边框卡片 |
| YISA SaaS CRM 后台管理 | 锦钰鑫鑫 | 产业园区 CRM | 0→1 上线项目；单一品牌色 + 中性灰 + 少量强调色 |

> 三页均为图片画廊，无法还原像素级配色，但其「单一主色 + 中性灰 + 极少量功能色」的克制风格是 B 端行业共识，与本项目「薄荷绿平台色」方向不冲突——问题在**执行一致性**而非方向。

### 1.2 补充：「医器云」系统专项（应补充请求新增）

- **可确认元数据**：作品名 SaaS 产品-「医器云」系统；作者 Andy丶子陌（北京/UI 设计师，站酷推荐设计师+终身会员+PRO）；2 年前发布，4409 浏览；医疗器械行业 SaaS。
- **医疗器械 SaaS 通用设计语言（推断·行业配色心理学）**：临床/医疗场景普遍用冷色系（蓝/青/绿）+ 大量中性灰白，传递洁净、可信、冷静；**绿色**象征生命/平衡/安心——与本项目薄荷绿品牌色心理暗示高度契合，方向正确。功能色（红/黄/绿）在医疗/工业语境里是「安全编码」，需高对比、强一致。
- **启示**：保留单一薄荷绿平台主色，但必须消灭「同 token 不同值」「硬编码蓝/紫/橙」乱象，否则功能色会失去安全编码意义；表单/表格密集型页面（与医器云最相似）应优先应用按钮收敛 + 长表提效 + 就地管理规范。

### 1.3 文章《企业级 SaaS「工作台」的设计观察》（群核科技 MCUX，方法论价值最高）

8 条可落地设计思想（子朔 / 杭州 / 产品设计师）：

1. **双工作台架构**：业务前台（Staff 生产）与管理后台（Admin 管理）分离，避免权限与功能耦合。
2. **个性化 + 场景化**：按角色/场景自动呈现相关工具，降低信息过载。
3. **数字资产（DAM）阶段设计**：售前（价值传递）→ 初始化（预置典型案例）→ 使用（低噪音引流）→ 下线（定期评估）。
4. **Staff vs Admin 差异**：Staff 默认隐藏移动/删除等管理动作、选中后才现；Admin 默认展示批量操作 + 全字段筛选。
5. **长表格提效**：字段显隐/排序、自定义列宽、关键列与操作列固定。
6. **隐藏提效操作**：框选+快捷键、单元格快速编辑、拖拽排序。
7. **设置「就地管理」**：设置分散到各模块旁，而非集中一处。
8. **AI 克制使用**：用于非结构化任务（图像搜索、自动归档、表单自动填充），不在确定性标准操作里硬塞 AI。

> 对标结论：本项目已具备「双工作台 / 角色壳（platform/client/agent）」正确骨架（AGENTS.md ROLE-SHELL-LOCK-01），**架构方向对，错在视觉层把角色壳配色搞乱了**——这是 P0 问题的根因。

## 阶段二：本项目设计系统深度扫描结果

### A. 配色令牌：多套并存、同名不同值（最严重）

**前端 `frontend/`（营销站）** —— 同一语义变量被多次重定义，同名不同值：

| 变量 | 位置 | 值 | 问题 |
|------|------|-----|------|
| `--color-primary` | `assets/css/main.css:4` | `#0f172a`（近黑） | 被当主按钮背景 |
| `--color-primary` | `assets/css/luna-tokens.css:124` | `teal #0f766e` | 作用域重绑覆盖 |
| `primary`(Tailwind) | `tailwind.config.ts:22` | `#3b82f6`（蓝） | 同名，值不同 |
| `--saas-primary` | `assets/css/saas-marketing.css:5` | `#2563eb`（蓝） | 又一套主色 |
| `--b2b-primary` | `assets/css/b2b-industrial.css:7` | `#1e3a5f`（深海军蓝） | 又一套主色 |

🔴 关键冲突：`main.css` 的 `--color-primary` 是**近黑 #0f172a**，Tailwind 的 `bg-primary` 是**蓝 #3b82f6**，同站渲染出「黑按钮」和「蓝按钮」两种主操作。

**后台 `frontend/admin/`（SaaS 后台）** —— 主色在「紫→蓝灰→薄荷绿」间反复迁移，残留散落：

### B. 按钮系统：三套并存 + 硬编码冲突

**前端（3 套按钮样式不统一）**
- `components/ui/Button.vue`（Tailwind）：`default=bg-primary(蓝)`、`destructive=bg-red-500`（⚠️ 未走令牌 `destructive:#ef4444`）
- `assets/css/main.css:154-261`：`.btn-primary`(黑)/`.btn-secondary`(蓝) + 聚焦环用**橙色** `rgba(234,88,12)`（蓝按钮配橙环，视觉噪音）
- `assets/css/saas-marketing.css:51-96`：`.saas-btn-*`（蓝 #2563eb）
- 三处圆角/尺寸/主色取值不完全一致

**后台（Ant `a-button` + 覆盖层 + 遗留硬编码）**

- `style.css:166-173`：`gradient-secondary`(紫)/`gradient-accent`(橙) 等废弃渐变仍在

🔴 最直观线上 Bug：以超管身份进后台，主题是薄荷绿，但凡用 `style.css .btn-primary` 的页面按钮是蓝色——主操作按钮颜色与整站品牌色不一致。

## 阶段三：完整改进方案

### 3.1 设计令牌：建立单一真源（Single Source of Truth）
- 前端：以 `assets/css/main.css` 为唯一真源，`--color-primary` 由 `#0f172a` 改为薄荷绿 `#4a9b8c`，删除 `luna-tokens.css` 作用域重绑、`--saas-primary`/`--b2b-primary` 独立定义，Tailwind `primary` 同步改为 `#4a9b8c`。
- 后台：以 `design-tokens-v3.scss`（LOCKED）为唯一真源，删除旧 v1/v2 引用；`style.css` 的 `.btn-primary` 改为 `var(--uj-brand)`，删除所有 `#2563eb` 硬编码；Tailwind `primary` 指向 `--uj-brand`，废弃 sky/紫/橙旧板。
- 语义功能色统一：`success #10b981` / `warning #f59e0b` / `danger #ef4444` / `info #2563eb`（前后端共用）。

### 3.2 按钮系统：收敛为一套规范
- 前端保留 `Button.vue` 为唯一按钮组件，删除 `main.css`/`saas-marketing.css` 的 `.btn-*`/`.saas-btn-*`。
- 后台保留 Ant `a-button` + mint-glass 覆盖，删除 `style.css` 的 `.btn-primary`/`.btn-danger`/`.gradient-*` 硬编码。
- destructive 统一走 `var(--color-danger)`；聚焦环跟随主色（如 `0 0 0 3px rgb(74 155 140 / .35)`），不再用错位橙色。
- 主操作每屏 ≤1 个高亮，次要用 `default`/`text`，破坏性用 `danger`。

### 3.3 SaaS 交互配色规则（角色 accent + 全局语义色）
| 层级 | 规则 | 取值 |
|------|------|------|
| 全局语义色 | 全角色一致 | success `#10b981` / warning `#f59e0b` / danger `#ef4444` / info `#2563eb` |
| 角色壳 accent | 仅用于壳级品牌（顶栏/侧栏 logo/主操作） | platform 薄荷 `#4a9b8c` / client 蓝 `#2563eb` / agent 青 `#0d9488` |
| 约束 | accent 不污染语义色 | — |
| 用户自定义 | 限定预设调色板 + WCAG AA 对比度校验（白字 on 主色 ≥ 4.5:1） | — |

### 3.4 布局与暗色修复
- 删旧 Vben 布局壳死代码（确认无引用后）；前端暗色补全 `[data-theme=dark]` 变量或移除模块；z-index 集中为令牌；设置补充「就地」入口。

### 3.5 对比度与一致性校验（落地前必做）
- 脚本统计两前端所有硬编码 hex，逐个确认是否改令牌。
- 对「浅灰文字 + 浅底」组合跑 WCAG AA 校验（正文 ≥ 4.5:1，大字 ≥ 3:1）。
- CI 加 lint 禁止组件 `<style>`/Tailwind 任意类出现裸 hex（除令牌文件）。

### 3.6 落地步骤
1. **P0（1 天）**：`main.css --color-primary` 近黑→薄荷；删 `style.css` 硬编码蓝/紫/橙按钮；后台 Tailwind `primary` 指向 `--uj-brand`。
2. **P1（1–2 天）**：收敛前端 3 套按钮为 1 套；修复聚焦环；destructive 走令牌；前端暗色补全或移除。
3. **P2（2–3 天）**：删旧布局死代码；建令牌校验 lint；角色 accent 预设调色板 + 对比度约束；长表格/就地设置等体验优化。

## 总结论

1. **方向正确，执行混乱**：本项目「薄荷绿平台色 + 角色壳（platform/client/agent）」架构与站酷企业级 SaaS 主张一致，问题不在设计方向，而在**配色令牌被 5+ 套来源重定义、按钮被 3 套系统实现、残留历史紫/蓝灰/蓝/橙硬编码**。
2. **最该先修的 3 件事（P0）**：① 前端 `--color-primary` 近黑 → 薄荷；② 后台 `style.css .btn-primary` 蓝 → 薄荷；③ 删除 Tailwind/style.css 旧紫/蓝灰/橙残留。改完即消除「同站主色不一致、同壳按钮与主题割裂」核心观感。
3. **B 端 SaaS 设计语言**：克制——单一主色 + 中性灰 + 极少量功能色；AI/个性化作增强而非干扰。令牌统一后可进一步落地「长表格提效、就地管理、阶段化引导」等交互层优化（源自 Page3 八条方法论）。
4. **外部真实反馈佐证**：Page2「干净但看不清」、Page4「导航贴边」直接印证本项目 P1 级对比度与布局细节风险，优先级被外部样本加强。
