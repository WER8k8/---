# 软著登记 · AI 合规与 2026 新规应对（优丁 SaaS）

> **联合**：产品经理 · 合规 · 架构  
> **更新**：2026-06-01  
> **免责声明**：以下为工程与产品合规操作指引，**不构成法律意见**；最终以中国版权保护中心当年表格与律师意见为准。

---

## 一、先澄清：「AI 30% + 人工 70%」是什么？

| 说法 | 真实含义 | 是否官方 |
|------|----------|----------|
| **「AI 30% 人工 70%」** | 民间/代办机构传的「比例」，**版权中心无此条文** | ❌ 非国标 |
| **查重重复率 30% 以内** | 与**已登记软著**比对，通用框架段重复低风险 | ✅ 审查实践（非 AI 比例） |
| **2026.3.15 手写承诺** | 「**未使用 AI** 编写代码、撰写文档、生成申请材料」 | ✅ 新版申请表要求 |
| **失信惩戒** | 虚假承诺 → 版权登记失信名单 + **个人征信** | ✅ 协会/中心通报 |

**PM 口径**：没有「AI 写到 30% 就安全」的计算器；**送审材料**必须按 **人类独立开发 + 可举证** 来准备。超了不是简单驳回，而是 **拉黑风险**。

---

## 二、2026 新规对优丁意味着什么

### 2.1 三条硬红线

1. **源代码鉴别材料（前 30 页 + 后 30 页）** — 须体现 **人类架构与业务逻辑**，不能是 obvious 模板/Stub/一键生成页。  
2. **说明书（操作手册）500～1300 字** — **禁止 AI 生成套话**；须与真实菜单、截图、API 一致。  
3. **签章页手抄承诺** — 经办人 **黑色笔手抄全文 + 签名 + 身份证号**；禁止打印、代签、AI 代写。

### 2.2 与「集百家所长 / Cursor 开发」的冲突点

| 做法 | 软著风险 |
|------|----------|
| 整库 fork Vben 当提交主体 | 高 — 非独创、查重易撞 |
| 234 路由 Stub / toast 页进 60 页 | 高 — 无实质逻辑 |
| AI 写说明书 + AI 填申请表 | **极高** — 直接踩承诺红线 |
| 「AI 软著一键生成」代办 | **极高** — 批量失信打击对象 |
| FastAPI 自研业务 + BFF + 算法 | **低** — 宜作为提交核心 |

## 三、优丁怎么整 — 五步法（可执行）

### Step 1 · 定「登记软件」边界（拆件，不整仓）

建议 **2 件**（与 `项目计划书` 一致），**各备独立 60 页**：

| 软著名称 | 提交代码范围（人类核心） | **不要**塞进 60 页 |
|----------|--------------------------|-------------------|
| **① AI-SaaS 智能营销平台 V2.0** | `backend/app` 租户/产品/询盘/SEO/发布/权限；`admin_bff`；`frontend` 四壳+BFF 接线+kit | 整包 Vben、`_ref/`、Stub 实验室、cognitive 空壳 |
| **② AI 内容/调度引擎**（可选第二件） | `services/ai_engine*`、UBrain 调度、多模型路由、prompt/usage | agent-hub 演示页、Math.random 已清但逻辑空洞处 |

**原则**：登记的是 **「优丁自研模块」**，不是「GitHub 合集」。

---

### Step 2 · 人工「净化」60 页源代码（登记专用，≠ 全仓库）

**操作**（研发 + 合规）：

1. 用脚本从指定目录导出 **连续 60 页**（每页 ≥50 行，等宽 10pt）。  
2. **前 30 页**：从 `main.py` / 应用入口 → `core/security` → `tenants/products/inquiries` 业务路由。  
3. **后 30 页**：`admin_bff/menu_adapter`、多租户、SEO 矩阵、发布服务、**自研算法/调度** 结尾。  
4. **剔除**：emoji 菜单 layout、drag-module 内存页、overview 空壳、大段 copy 开源 LICENSE 头无自研注释。  
5. **脱敏**：密钥、内网 URL、真实手机号。  
6. **页脚**：`优丁建材有限公司 版权所有 ©2026` + 连续页码。

**人工复核清单**（每条须真人签字「我读得懂这段逻辑」）：

- [ ] 每文件至少 1 处 **业务向注释**（中文，非 AI 万能注释）  
- [ ] 无整段与 Vben/Element 官方 demo **逐字相同**  
- [ ] 无 `TODO` / `demo` / `stub` / `Math.random` 主导页面  
- [ ] Git `blame` 对应提交者为 **登记经办人或核心研发**（非 bulk bot）

---

### Step 3 · 开发痕迹证据包（防抽查、防失信）

与申请表 **同时归档**（不提交中心，内部留存；抽查可出示）：

| 证据 | 路径/动作 |
|------|-----------|
| Git 连续历史 | `上线网站` 主仓 log；关键模块 ≥6 个月迭代 |
| 需求/架构 | PRD、UAC 蓝图、四壳治理、BFF 设计 |
| 人工评审 | Code Review 记录、PM 签字、ECC 纪要 |
| 设计稿 | Bento spec、tokens（证明 UI 人类设计） |
| 开源声明 | `OPEN-SOURCE-NOTICES.md`（Vben/Art/Formily 仅「引用」） |
| 经办人能力 | 经办人能 **口头解释** 60 页内 3 个核心函数 |

**禁止**：临时刷 500 行 git commit 一天造「痕迹」— 审查看时间线合理性。

---

### Step 4 · 说明书 / 功能说明（500～1300 字，人类写）

**必须人类撰写**（可参照结构，不可 AI 一键出稿）：

1. 研发背景（建材外贸 SaaS 痛点）  
2. 核心架构（FastAPI + 多租户 + 四壳 + BFF，**勿夸大未上线能力**）  
3. 技术实现（JWT 权限、SEO 矩阵、发布 Worker — 与 60 页代码对应）  
4. 应用场景（租户/代理/超管 — 与 **送检鉴定面** 截图一致）  

**配图**：只用 **S0 改造后** 截图；禁止 Stub 页、彩虹 KPI、实验室菜单。

模板见：`docs/软著/源代码文档.md`（须按 2026 字数扩写，非 AI 填充）。

---

### Step 5 · 签章与经办

| 项 | 要求 |
|----|------|
| 经办人 | **真实核心研发或技术负责人**，能背代码逻辑 |
| 手抄承诺 | 按 **2026 新版申请表原文** 全文手抄 |
| 一致性 | 申请表 ↔ 说明书 ↔ 60 页代码 ↔ 截图 **四处一致** |
| 代办 | 禁止低价「100% 下证」AI 代办；材料造假 = 失信 |

## 四、AI 辅助开发 vs 软著 — PM 合规边界

| 允许（行业常见） | 不允许（登记红线） |
|------------------|-------------------|
| AI 查文档、生成 **草稿** 后 **人类改** | AI 生成 60 页 **不审直接交** |
| AI 补全单元测试，人类 review merge | AI 写说明书/申请表 **整篇提交** |
| Cursor 写 BFF 样板，人类改业务规则 | 承诺「未使用 AI」却全程无人类 commit |
| 开源 fork + **人类写 adapter/业务** | fork Vben **原样** 当软著主体 |

**记忆口诀**：**AI 做草稿，人类做作者；登记看 60 页，不看全仓 33 万行。**

---

## 五、查重 30% 与 AI 比例的区别（别混）

- **查重 30%**：相对 **其他已登记软著** 的重复度；通用 SDK/连接池重复可解释。  
- **核心业务逻辑重复 >30%**：人工复审，易补正/驳回。  
- **>50%**：极高驳回率。  

**优丁动作**：

- 60 页以 **自研 backend + BFF + 业务** 为主，重复主要在框架 import（可接受）。  
- **不要** 把 Vben `accessible.ts` 等原样 30 页贴进去。

## 六、与省级评测（GB25000）的关系

| 项目 | 软著 | 省级软件评测 |
|------|------|--------------|
| 目的 | 著作权归属 | 质量/功能/文档 |
| AI 承诺 | 2026 手写严格 | 看功能真实性、手册一致 |
| 材料 | 60 页代码 + 说明书 | 演示脚本 + 截图 + 自测报告 |
| 优丁策略 | **鉴定面截图** 同时服务评测与手册配图 | S0 改造后再拍 |

**两件一起准备**，但 **代码 60 页筛选标准相同**：只展示成熟、人类可解释模块。

## 八、PM 汇报一句话

> **没有「AI 30% 就过」的官方比例；2026 起看的是「人类独立开发」承诺 + 60 页独创性 + 材料一致。**  
> 优丁策略：**拆 2 件软著、60 页只交自研 FastAPI/BFF/核心业务、说明书人类写、Stub/Vben 整库不进鉴别材料、留 Git 证据链** — 才能同时避开通用查重和失信拉黑。
