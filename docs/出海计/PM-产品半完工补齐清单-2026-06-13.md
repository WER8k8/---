## 一、为什么「系统里好多地方开发到一半」

这不是单一 Bug，而是 **三类缺口叠在一起**：

| 类型 | 表现 | 谁补齐 | 研发能否自驱 |
|------|------|--------|--------------|
| **A. 导航指数 ≠ 商用完成** | 超管工作台 ~81 个入口、侧栏很长，点进去只有壳或 mock | 产品定 **送检面 / 实验室 / Kill** | ❌ 须 PM 矩阵 |
| **B. PM 签字 / Owner 决策未闭合** | 代码路径已有，但平台表、套餐价、演示域、矩阵未签字 | **PM + Owner** | ❌ 阻塞验收与对外口径 |
| **C. 研发收尾 / 上游未接** | API 503、TTS 无音频、FCM 未配、Capacitor 未发包 | 研发蜂群 | ✅ 有规格后可排期 |

**铁律（宪章）**：Sprint A～O **84/84 已闭合** ≠ 产品 **200 权重满格**；当前约 **78%**（`module-progress.json`）。  
对外演示 **禁止** 以实验室菜单为主叙事（`docs/产品经理-开发文档.md` §结论）。

## 四、按域划分的「半完工」地图（给产品排优先级）

### 4.1 送检主链（应优先补齐规格 + 验收，非砍功能）

| 域 | 完成度 | 产品要定什么 | 研发剩什么 |
|----|--------|--------------|------------|
| 开通/支付/套餐 | 高 | 套餐价签字 | 发票 PDF（P1-08） |
| 独立域 SSL | 高 | 演示域 Owner | 实机 certbot 一轮 |
| 多平台发布 | 高 | 40 平台表 | Worker 生产观测 |
| 询盘 IM | 中高 | 全渠道话术 | StickyImBar 租户站统一（P1-01） |
| 订单/物流 | 中高 | 物流商选型 | LBS/报价单子页深化 |
| 财务/分润 | 高 | 对账模板确认 | 生产 SMTP（P1-07） |
| 建站/图片空间 | 中高 | BJ-01 五问签字 | Formily 边界冻结 |
| **出海计 App** | 中高 | 商店图/推送策略 | Capacitor 包 + FCM |

### 4.2 实验室（默认隐藏 — 产品须先定 Kill 或 PlanGate，再派研发）

共 **24 组前缀**（`PLATFORM_LAB_PREFIXES`），含：geo-engine、media-factory、cognitive、edge-cdn、developer、globalization、agent-hub、code-tools、automation 等。

**产品三选一（每条路径）**：

1. **Kill** — 从菜单与工作台剔除  
2. **PlanGate** — 标 Enterprise/W3，未开通显示升级页  
3. **Lab** — 仅 `admin_lab_enabled=1` 可见，响应必须 mock/503 标注  

未选之前，研发 **不得** 做成「看起来已上线」。

### 4.3 SEO / GEO（半真半示意 — 产品须写「能给客户看什么」）

见 `docs/admin-seo-geo-data-trust-map.md`。  
产品需单独一页：**哪些菜单可进销售话术、哪些仅内部参考**（尤其百度站长 mock、schema/eeat 示意页）。

### 4.4 租户 Stub（6 条 — 产品定套餐门控）

`/client/media-factory`、`article-to-video`、`egress`、`ai-scenarios`、`app`、`copilot` — 策略已在 `CLIENT_STUB_RULES`，**套餐名与文案需产品填齐**。
