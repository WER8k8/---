# UBrain-X × DeerFlow × Accio Work 全维度能力蓝图

> 2026-05-25  
> 来源：用户给出的 Accio Work 全维度核心能力清单  
> 定位：把 Accio Work 的“AI 大脑 + 自动化团队”范式，改造成 **建材卖货 OS 的获客与运营智能体舰队**。  
> 北极星：**客户自有网站带来的有效电话 / 询盘数量**，其次才是效率、合规、自动化。

---

## 一、总原则

1. **不把 Accio 名字当卖点**：客户不买概念，客户买电话、询盘、成交。  
2. **不承诺阿里国际站私有能力**：没有官方 API / 授权时，只做等价工作流、草稿、人审、导入。  
3. **敏感动作必须确认**：发信、发帖、报价、改价、付款、报关、税务、合同，默认 **人点确认**。  
4. **所有智能体写回本系统账本**：`inquiries`、`publish_tasks`、订单、报价、线索来源、周报。  
5. **优先级按电话排序**：先获客、询盘、内容、线索复盘；后 VAT、风控、动态定价。

---

## 二、产品形态：一个工作台，六类智能体

对外名称建议：**优丁卖货副驾 UBrain-X**。

```text
客户一句话
  → Accio Work 形态的副驾工作台（/client/copilot）
  → UBrain-X 识别意图与权限
  → DeerFlow 执行长任务 / 子智能体并行
  → 本系统写回线索、内容、发布、订单、周报
```

| 智能体 | 第一目标 | 电话相关性 | 当前落地优先级 |
|--------|----------|------------|----------------|
| 市场智能体 | 找市场、竞品、细分品类 | 中 | P1 |
| **获客智能体** | 找采购商、筛高意向、开发信 | **高** | **P0** |
| **运营智能体** | 内容、独立站、社媒导流 | **高** | **P0** |
| 合规智能体 | 单据、条款、VAT/报关提醒 | 中 | P2 |
| **客服智能体** | 7×24 回复、询盘跟进、物流推送 | **高** | **P0/P1** |
| 风控智能体 | 信用、欺诈、交易审核 | 中 | P2 |

## 三、能力全表：Accio 清单 → 本系统实现路径

### 1. 全链路智能体协同自动化

| Accio 能力 | UBrain-X 等价实现 | 边界 |
|------------|-------------------|------|
| 全球市场需求分析 | `market_research_agent`：按品类/国家生成需求、价格、竞品摘要 | 数据先来自公开搜索/内部知识库，非阿里站内数据 |
| 竞品调研、细分市场定位 | 竞品站点/关键词/内容结构对比，输出“保温板中东/东南亚机会” | 先报告，后自动抓取 |
| 海外采购商挖掘 | `buyer_lead_agent`：公开 B2B 目录、展会名单、客户上传名录清洗 | 不承诺阿里采购商库 |
| 多轮商务谈判 | `negotiation_draft_agent`：生成邮件/WhatsApp 草稿、反报价策略 | 人确认发送，不自动签约 |
| 高意向客户筛选 | 已落地 `inquiry_score`，后续加模型和聊天记录导入 | 不跨租户训练 |
| 多语言内容生成 | `lead_content_pack` 扩展到英/阿/西/俄 | P0 先中文/英文，其他语种 P1 |
| 独立站搭建 | 复用租户独立域、CMS、落地页模板 | P0 先保温厂模板 |
| 社媒自动化引流 | `matrix_publish` + 发布 Worker + 5+5 平台 | 默认人审，避免封号 |
| 跨境报关/VAT | 合规清单、单据模板、风险提示 | 不自动申报，除非接持牌接口 |
| 7×24 多语言询盘响应 | 询盘草稿 + 模板 + 夜间自动首回（需客户开启） | 高风险行业默认人审 |
| 售后处理、物流推送 | 订单/物流状态模板推送 | 需真实物流 API |
| 客户信用风险识别 | 邮箱域名、国家、付款条款、黑名单提示 | 不做征信结论 |
| 供应链欺诈预警 | 异常账号/重复电话/高风险国家/钓鱼关键词 | 仅预警，不自动拒单 |
| 交易审核 | 报价、账期、收款方式风险提示 | 人决策 |

### 2. 零门槛自然语言交互

| 一键调用模块 | Accio 形态任务卡：预览 → 确认 → 执行 → 写回 |

### 3. 多区域多场景适配

| 能力 | 落地 |

| 多语言 | P0 中/英；P1 阿/西/俄；P2 更多语种 |

| 支付/物流习惯 | 国家画像：中东账期、欧美合规、东南亚小单快反 |

### 4. 数据驱动增长

| 能力 | 落地 |
|------|------|
| 全链路报表 | `weekly_lead_report` 已有后端雏形；P0 出 CSV/卡片 |
| 动态定价 | P2：汇率、成本、竞品、物流加权，先给建议不自动改价 |
| 客户生命周期 | P1：新线索、已报价、沉默、复购提醒 |
| 流失挽回 | P1：超 7 天未回/未报价自动提醒和草稿 |

### 5. 生态集成与扩展

| 能力 | 落地 |
|------|------|
| 阿里国际站 | P2/P3：官方 API / 手工导入；无授权不黑盒爬敏感数据 |
| PayPal / 物流商 | P2：支付/物流 API 插件 |
| API 嵌入建材 OS | 本系统原生：FastAPI + UBrain 工具注册表 |

### 6. 效率与成本革命

| 能力 | 落地 |

| 小单快反 | P0：长尾内容 + 询盘分级 + 快速报价草稿 |

### 7. 多平台多账号管控

| 能力 | 落地 |
|------|------|
| 多平台账号统一管理 | P1：5+5 平台账号与发布任务 |
| 规避账号关联风险 | P1/P2：`browser_profile` + static IP 槽位；只做合规隔离，不做违规规避 |

## 四、分期交付（按电话优先）

### P0 — 14 天：保温厂获客副驾

目标：先让自有保温建材站 **能更快产内容、接住电话、分清来源**。

| 项 | 状态 |
|----|------|
| `lead_content_pack` 获客内容包 | 后端已落地 Phase 0 |
| `geo_submit_pack` GEO 执行清单 | 后端已落地 Phase 0 |
| `matrix_publish` 矩阵发布计划 | 后端已落地 Phase 0 |
| `inquiry_score` 询盘意向分级 | 后端已落地 Phase 0 |
| `weekly_lead_report` 周报 | 后端已落地 Phase 0，需前端展示 |
| 手机号必填、来源追踪、CSV 导出 | 必须补齐 |
| `/client/copilot` 工作台 | 待做 |

验收：至少 1 条真实手机号进系统，且来源可见。

### P1 — 30～60 天：Accio 形态工作台

| 项 | 说明 |
|----|------|
| 工作台任务卡 | 对话、预览、确认、执行、结果 |
| DeerFlow 队列 | 长任务异步执行，状态可查 |
| 5+5 平台发布 | 先人工/半自动，后 Worker |
| 多语言开发信 | 中/英先行，阿/西/俄后续 |
| 客户生命周期 | 未回、已报价、沉默客户提醒 |

验收：每周至少节省 3 小时内容/跟进时间；线索周报可给客户/政府看。

### P2 — 3～6 月：跨境运营与合规增强

| 项 | 说明 |
|----|------|
| 市场智能体 | 国家/品类/竞品报告 |
| 合规智能体 | 报关/VAT/贸易条款模板与提醒 |
| 风控智能体 | 欺诈、信用、付款风险提示 |
| 动态定价 | 建议价，不自动改价 |
| 平台账号隔离 | browser profile + static IP 槽位 |

验收：可作为收费增值包，不影响 P0 获客主线。

### P3 — 6～12 月：生态插件

| 项 | 说明 |
|----|------|
| 阿里国际站 / 1688 官方插件 | 需要授权或合作 |
| PayPal / 物流商 | 真实 API 对接 |
| 桌面执行壳 | 大客户或自用可选 |

## 五、对外话术（谦逊版）

> “我们不是照搬阿里国际站的数据能力，而是把 Accio Work 的工作台范式、DeerFlow 的长任务执行、UBrain 的建材业务大脑，落到自己的独立站获客闭环里。第一阶段只验一件事：电话和询盘是否进系统、来源是否可复盘。”

禁止说：

- “完全复刻阿里国际站全部能力”
- “一个人替代完整跨境团队”
- “自动报税、自动砍价、自动成交”
- “保证一个月多少电话”

## 六、技术底座需求

| 层 | 需求 |
|----|------|
| Orchestrator | UBrain 工具注册、权限、确认门 |
| DeerFlow | Docker 沙箱、任务队列、日志、状态回写 |
| Data | 线索、来源、客户生命周期、发布任务、审计日志 |
| Frontend | `/client/copilot`、任务卡、周报卡、确认弹窗 |
| Security | 租户隔离、敏感动作审批、Token 配额、操作审计 |

---

## 七、质量门槛

每个新增智能体必须有：

1. **电话/询盘相关指标**，或明确标注为 P2 增值能力。  
2. **人审/确认门**，除非是只读报告。  
3. **租户隔离测试**。  
4. **失败状态与重试**。  
5. **不可夸大对外话术**。

---

## 八、下一刀代码建议

按质量与获客优先：

1. `/client/copilot` 前端单页调用现有 UBrain 工具。  
2. 公开询盘接口强制手机号必填。  
3. `weekly_lead_report` 前端卡片 + CSV 导出。  
4. DeerFlow job 表与异步队列。  
5. CMS 草稿写入 `lead_content_pack`。
