# 先开发完整 · 问题总表与重设计门槛

> **立场（2026-05-28）**：上一版 [`架构设计-2026-目标架构与性能.md`](../adr/架构设计-2026-目标架构与性能.md) 里用 **Feature Flag / 实验室 / 501 占位** 来「显得架构合理」，本质是 **承认功能未做完却先画架构图**——不合理。  
> **正确顺序**：① 整合全部问题 → ② **按卖货主链把功能做完整** → ③ 达标后再做 **性能与域划分** 的架构重设计。

---

## 一、「开发完整」的定义（出口门槛）

满足以下 **全部** 条件，才允许启动「架构重设计」专项（BFF 拆分、域目录迁移等）：

| # | 门槛 | 验收（可脚本/可签字） |
|---|------|------------------------|
| G1 | **主菜单无空壳** | 四壳 + 租户四支柱内，点击任一菜单 **不得** 固定 501 / 空白页 / 仅「开发中」文案 |
| G2 | **主链 API 已挂载且非 stub** | 七步闭环相关接口返回真实数据或明确业务错误，**禁止** 硬编码假数字仪表盘 |
| G3 | **生产形态可跑** | Postgres + Redis + Celery + 备份 cron；`preflight --production` 仅允许「预期项」失败（如未配真 SSL） |
| G4 | **AI 可切换真 Key** | 配 Key 后副驾/生成 **非** 固定 Mock 文案（`QA-08`） |
| G5 | **L3 真人验收** | PM 对 [`演示验收清单.md`](../演示验收清单.md) 签字，含询盘导出实点 |
| G6 | **无「代码在、路由未挂」** | `check_mounted_routes` + 管理端页面与 API 对照表 **0 条** 🔌 未挂载 |
| G7 | **占位模块二选一** | 每项要么 **做完**，要么 **从默认菜单移除**（可进「实验室」但须 PM 书面列清单，且不算 G1 主链） |

**未达 G1～G7**：只做 **小步修复 + 单测**，不做大规模目录搬迁。

| **文档占位** | GraphRAG / Neo4j、NSN 部分叙事 | 无实装 | P2；**不进 G1 主菜单** |

| **双栈重复** | `seo-backend` Node vs FastAPI | 认知成本高 | 能力迁移完再下线 Node，**不是** Flag 隐藏 |
| **页面多、链未闭** | ~195 管理端页、财务中台、枢纽站、content_master | 卖货链未产品化 | 见下文 **Phase 1 主链** |
| **架构掩饰** | 用实验室 Flag 藏未完成模块 | 制造「快」假象 | **禁止**；未完成就从默认菜单拿掉 |

### F. 架构层（**暂缓**，等 G1～G7）

| 原建议 | 为何暂缓 |

| BFF bootstrap | 聚合空壳 API 只会 **更快看到 501** |

## 三、开发完整 — 推荐执行顺序（只做实事）

### Phase 0 · 冻结叙事（1 天，PM+研发）

- 列出 **主链菜单**（四支柱 + 超管 Tab A/B）最终名单。  
- 名单外能力一律标 **「实验室 / 未承诺」**，不写进对外材料。  
- 更新 [`问题汇总与任务表.md`](./问题汇总与任务表.md) 为本文件链接。

### Phase 1 · 卖货七步闭环（4～6 周，功能完整）

按 [`未开发任务清单.md`](../未开发任务清单.md) **P0** 与七步表，优先：

| 序 | 能力 | 关键交付 |
|----|------|----------|
| 1 | 统一发布 + 40 平台 | 母版 `content_master` 或等价、发布 Worker 真消费、平台 seed 生产可用 |
| 2 | 询盘 | 仅 **unified** 入口；导出可用；与 IM 配置通 |
| 3 | 租户域 + SSL | Host 解析、HTTPS（演示域 PM-04） |
| 4 | 订单 + 物流 | `GET /logistics/track` 或对接；前台 API 基址环境化 |
| 5 | 支付/套餐/冻结 | 付费 → 配额；到期冻结 |
| 6 | 飞轮 D2～D6 | **UI 实机** + 有 Key 时真 AI（非仅 Mock） |
| 7 | 呼朋唤友 | referral 已挂；与计费打通（P1-12） |

**每周**：`pytest unit` + `run-full-checklist.ps1` + **更新未开发清单勾选**。

### Phase 2 · 去空壳（2～3 周）

| 项 | 动作 |
|----|------|
| Accio 4×501 | 实现最小可用 **或** 从 Accio 菜单移除 |
| SEO stub | 接库 / 删页 / 标 demo |
| 实验室页 | 未做完的 **默认不显示**（路由仍存在，PM 清单登记） |
| GraphRAG 等 | 保持 P2 文档，不宣传 |

### Phase 3 · 生产与商用门禁（2 周，运营+研发）

- Postgres、Alembic、Redis、Celery、备份、`preflight --production`  
- PM L3 全签字、`QA-08`  
- 专家团 **第三轮评审**（见下）

### Phase 4 · **架构重设计**（G1～G7 通过后，2～3 周）

- 再启用 [`架构设计-2026-目标架构与性能.md`](../adr/架构设计-2026-目标架构与性能.md)  
- 实施 BFF、缓存、懒加载、域目录 — **此时才是合理时机**

## 六、给团队的一句话

> **快** 来自 **请求少、缓存、异步**；  
> **完整** 来自 **主链没有 501、没有假仪表盘、没有 Mock 当商用 AI**。  
> 先完整，再重设计；用 Flag 藏空壳 = 技术债伪装成架构，不做。
