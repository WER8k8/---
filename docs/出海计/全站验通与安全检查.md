## 一、什么叫「全程跑通」

分三层，避免和「商用上线」混为一谈：

| 层级 | 含义 | 怎么验 |
|------|------|--------|
| **L1 代码门禁** | API/服务逻辑在测试环境一致 | `pytest`（见下表） |
| **L2 运行冒烟** | 本机或预发**真启动**后端，走 HTTP | 启动 uvicorn + 下面脚本 |
| **L3 浏览器全程** | 租户站 + 管理端 + 副驾**人工点一遍** | 清单 §四（约 30–60 分钟） |

**PM 签字、演示域、套餐定价**：按你的要求 **本轮不做门禁**。

## 三、安全 /「没有漏洞」说明

**不能**用单元测试代替安全审计。本仓库已有：

| 类型 | 位置 | 作用 |
|------|------|------|
| 设计审计文档 | `docs/安全审计报告.md` | OWASP 清单（设计层） |
| 中间件 | 限流、WAF 模式、登录防暴力、JWT | 运行时 |
| 就绪检查 | `production_readiness_service` | 弱密钥、支付严格模式、路由挂载等 |
| 单测 | `tests/unit/test_security_auditor.py` | AI 审计服务逻辑（非全仓扫洞） |

**建议最低安全复验（上线前自己跑）**：

```powershell
$env:JWT_SECRET_KEY = "<至少32位随机>"
$env:ENVIRONMENT = "production"
cd backend
python -m pytest tests/unit/test_auth.py tests/unit/test_security_auditor.py -q
cd ..
python scripts/run_production_preflight.py
```

预检 **fail** 的项（弱密钥、未配 SMTP、备份目录等）按提示修 `.env`，而不是忽略。

**真漏洞**还需：依赖扫描（`pip audit`）、HTTPS 头检查、授权越权用例（租户 A 不能看租户 B 数据）——L3 人工 + 可选专业渗透。
