# 蜂群 P3 商业闭环（2026-05-31）

## 范围

| 编号 | 能力 | 状态 |
|------|------|------|
| W13 | 平台落地页 `/landing` 联系表单 → `POST /inquiries/public` | ✅ |
| W14 | 支付宝 `alipay.trade.precreate` + `channel=alipay` 贯通 | ✅ |

## W13 落地页线索

**前端** `frontend/admin/src/views/landing/index.vue`

- 表单字段：姓名、手机号（11 位校验）、邮箱、公司、需求描述
- 提交：`POST /api/v1/inquiries/public`
- 归因：`source_channel=platform_landing`，`landing_path` 为当前路径
- 公司名写入 `product` 字段，便于后台询盘列表筛选

**后端** 复用既有 `InquiriesUnifiedService.create_public_lead`，自动触发 `notify_new_public_inquiry` 推送。

## W14 支付宝 Native

**服务** `backend/app/services/alipay_client.py`

- RSA2 签名 / 验签（`cryptography`）
- `create_precreate` → 返回与微信对齐的 `code_url`
- 未配置商户密钥时：遵循 `PAYMENT_ALLOW_MOCK` 返回 mock 二维码
- `verify_notify`：严格模式下校验异步通知签名

**贯通点**

| 入口 | 变更 |
|------|------|
| `PaymentService.create_native_payment(channel=...)` | 微信 / 支付宝分流 |
| `PaymentService.create_token_pack_native` | 同上 |
| `POST /payment/create-native` | 请求体新增 `channel` |
| `POST /agent/collect-payment` | `channel=alipay` 真正走支付宝 |
| `GET /payment/channels/status` | 支付宝 `mock_allowed` |

**环境变量**（`.env.example` 已有）

```
ALIPAY_APP_ID=
ALIPAY_PRIVATE_KEY=
ALIPAY_PUBLIC_KEY=
ALIPAY_NOTIFY_URL=
ALIPAY_GATEWAY=https://openapi.alipay.com/gateway.do
```

沙箱网关：`https://openapi.alipaydev.com/gateway.do`
