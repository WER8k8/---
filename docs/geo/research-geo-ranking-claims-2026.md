## 一、结论先行（给决策层）

| 判断 | 说明 |
|------|------|
| **不堆平台年费是对的** | 工地集采毛利薄，6980 GEO + 1688/慧聪/阿里国际 VIP + 6 万出海代运营 ≈ 常见年毛利，必亏 |
| **6 万自投可以替代 6 万外包** | 条件：投在 **API/算力、1 条主视频渠道账号池、1 条主 B2B 渠道**，而非再买一个「全包承诺」 |
| **200+ AI 员工是优势** | 前提是 **编排进日更闭环**（选题→结构化文→多平台发→GEO 复测→改 FAQ/Schema），不是 200 个聊天窗口 |
| **「革命性更新」三件事** | ① 探测从「你认识品牌吗」→「用户问厂家，你推荐谁」② 覆盖豆包/通义/文心/Kimi/元宝 ③ 发布→收录→复测自动循环 |
| **国内 vs 国外一致内核** | 结构化、权威信号、统计数据、多源一致、可引用密度 — Princeton 论文与国内白皮书 **同向** |
| **国内特有增量** | 微信生态（公众号/视频号/小程序）对 **元宝类** 权重大；百家号/知乎/头条对 **百度/豆包** 训练与检索反哺 |

## 二、国内常见说法（公众号 / 白皮书 / 开发者社区）

### 2.1 共识定义（可采信）

- **GEO = Generative Engine Optimization**：优化对象是 **大模型生成与引用偏好**，不是传统 SERP 链接排序。
- **目标**：品牌在 AI 答案里 **被点名、被引用、被推荐**，而非仅「有收录」。
- **与 SEO 关系**：叠加层；SEO 长尾 + 结构化落地页仍是 GEO 的 **信源底座**。

来源归纳：腾讯云开发者社区 GEO 详解、网易「一句话讲透 GEO」、一搜百应类白皮书框架。

### 2.2 国内服务商高频「四原理」（部分可验证）

| 说法 | 机制解释 | 系统可落地 | 营销夸大风险 |
|------|----------|------------|--------------|
| 语义结构化 | FAQ、实体-属性-值、参数表、Schema | ✅ `llms.txt`、JSON-LD、Formily SEO 侧栏 | 低 |
| 权威信任 | 资质、案例、央媒/行业媒体、百科 | ⚠️ 需真实素材；软文 API 未接 | **「T0 央媒 45% 权重」多为经验公式，非官方公开算法** |
| 多平台适配 | 同一实体多源一致 | ✅ 内容矩阵 + 统一发布 | 「一次训练八端同步」夸大 |
| 事实密度 | 每 150–200 词 1 条可验证声明 | ✅ UBrain/出海参谋 Prompt 约束 | 低 |

### 2.3 平台差异化说法（2026 行业文）

**腾讯元宝 / 微信系（火山引擎开发者社区等文章归纳）**

- 强调 **社交语义**：公众号、视频号传播深度、互动、口碑语义。
- 信源梯队叙事：T0 央媒 ~45%、T1 垂直媒体 ~25%、T2 官方自媒体 ~20%、T3 UGC ~10%。
- **调研判断**：权重比例为 **行业推断**，但 **微信生态内容确实影响腾讯系 AI 产品** 方向可信 → 我方应 **公众号 + 视频号 + 官网同口径**。

**一搜百应类白皮书（6980 竞品常见话术）**

- 8 大模型 + 12 自媒体矩阵、FAQ Schema「引用率 +45–60%」、Organization Schema「+35%」。
- **调研判断**：Schema 有效 **有国外论文与国内实践支撑**；具体百分比 **不可作为 KPI 承诺**，只作优化方向。

**智推时代 / 微盟星启等（对标对象）**

- 卖点：**代运营 + 提交包 + 监测报表 + 电话承诺边界模糊**。
- **调研判断**：卖的是 **人力密度**；我方应用 **AI 员工 + 自动化** 换人力，用 **`inquiries` 可审计** 换模糊承诺。

### 2.4 应标记为「话术 / 不可承诺」

- 「保证 AI 排名第一 / 前三厂家」
- 「7 天见效、30 天霸屏」
- 「免费百度大词首页」（凤巢 + 百度系占 SERP）
- 「40 平台全自动已上线」（我方 MOD-03 约 45%，真实文本适配 7 家）
- 未标注来源的「权重百分比」

## 三、国外最新技术（可引用）

### 3.1 Princeton GEO 论文（KDD 2024, arXiv:2311.09735）

**核心**：黑盒优化框架 + GEO-bench（1 万 query）；在类 Bing Chat / Perplexity 上验证。

**有效 tactics（相对 baseline 可见度提升）**

| 策略 | 相对提升（论文） | 我方映射 |
|------|------------------|----------|
| Statistics Addition | ~**+41%** | 产品页参数表、工地案例造价/用量数据 |
| Quotation Addition | ~**+28%** | 客户证言、行业标准引用 |
| Cite Sources | ~**+30–40%** | 文内链向官网 FAQ、国标、检测报告 |
| Fluency / Authoritative tone | 中等 | Prompt + 人工抽检 |

**2025+ SAGEO**：生产级 retrieval 下 tactic 效果 **变小但仍有效** → 需 **持续迭代 + 多源**，非一稿永逸。

### 3.2 与 Perplexity / ChatGPT Search 生态

- 引用偏好：**可验证数据、清晰归因、多源交叉一致**。
- **Original research** 类内容 citation 更高（行业统计 2025–2026）。
- **我方出口场景**：英文 **Product spec + MOQ + lead time + port** 结构化页，优于纯营销散文。

### 3.3 国外 vs 国内对照

| 维度 | 国外（论文/Perplexity） | 国内（公众号/白皮书） |
|------|-------------------------|------------------------|
| 优化目标 | Citation / visibility in GE response | 同上 + 「推荐三家厂家」话术 |
| 核心信号 | Stats, quotes, citations, fluency | 同上 + Schema + 微信生态 + 百家号 |
| 评估 | GEO-bench, Position-Adjusted Word Count | 服务商自定义「收录率」 |
| 我方差距 | 探测 Prompt 偏「认识品牌吗」 | 缺国内主流模型探测 |

## 四、对「6 万天津大迈类 TK 矩阵」的判断

| 他们卖的 | 2026 H2 AI 能否替代 | 我方现状 |
|----------|---------------------|----------|
| 多账号 TK 矩阵 + 发布节奏 | **部分** — 文/图生视频已够用 | `media-factory`、`article-to-video`、`video-matrix` 有骨架 |
| 账号养号、限流申诉、平台政策 | **难完全替代** — 需 1 个懂平台的人 | Worker/Stub，未生产 cron |
| 英文/小语种脚本 + 本地化 | **可替代** — LLM + 模板 | UBrain / 出海参谋 |
| 询盘承接（WhatsApp/表单） | **可替代且更强** | 独立站 + `inquiries` 链 |

**建议 6 万自投拆分（示例）**

- ¥1.5万：视频生成 API + TTS + 混剪算力（年）
- ¥1.5万：DeepSeek/豆包/通义等 GEO+内容 API
- ¥2万：1 条 TikTok/视频号 **主战场** 投流测试（非全平台）
- ¥1万：1688 **基础** 或阿里国际 **低配**，二选一，不双开 VIP

## 五、「排名革命性更新」产品规格（P0）

### 5.1 GEO 探测 v2

**现状问题**（`geo_engine_service.py`）：Prompt 为「你是否了解该品牌」，不等于用户真实问法。

**改为标准 probe 集**（建材/出口各一套）：

```
用户：我要采购 [品类]，[地区/工地/项目类型]，请推荐 3 家可靠厂家并说明理由。
用户：Compare suppliers of [product] for export to [country], MOQ and lead time.
```

**输出 KPI**：是否被点名、排名位次（1/2/3）、引用来源 URL 是否含我方域/矩阵账号。

### 5.2 国内模型覆盖

| 模型 | 优先级 | 用途 |
|------|--------|------|
| 豆包 | P0 | 国内 B2B 问法 |
| 通义 | P0 | 阿里系商户 |
| 文心 | P0 | 百度系 |
| Kimi | P1 | 长文引用 |
| 腾讯元宝 | P1 | 微信生态问法 |
| DeepSeek/GPT/Gemini | 已有 | 出口 + 对照 |

### 5.3 闭环：发布 → 收录 → 复测

1. `geo_content_matrix` 生成结构化 FAQ 文  
2. 统一发布（先 **7 家真实适配** + 官网）  
3. 百度站长 / GSC 收录状态  
4. 7/14/30 天 **probe v2** 自动跑  
5. RankGuard 下降 → 回滚或补强 FAQ  

### 5.4 租户可见（非仅 super-admin）

- `/client` 仪表盘：**收录率、probe 通过率、竞品对比、近 30 天询盘**  
- 对齐 `promise_boundary`：**不承诺排名，承诺可复盘信号 + 线索资产**

## 九、平台数 × 排名优先 × 收益闭环（2026-06 增补）

### 9.1 准则

**排名优先于菜单数量展示**：catalog 可以 40+，但对外发布与 GEO 矩阵按 **`geo_weight × adapter_status`** 排序——先 live 高权重，再 stub 视频，再 exploration。

**收益闭环**：`GEO probe 通过 / 收录` → `询盘电话` → `租户开户/续费` → `再投入内容与平台适配`。

### 9.2 系统落地

| 模块 | 路径 | 作用 |
|------|------|------|
| 排名注册表 | `platform_rank_registry.py` | 各平台 GEO 权重 + 发布顺序 |
| 平台发现 | `platform_discovery_service.py` | catalog vs live 缺口 → 下一批适配器队列 |
| API | `GET /platforms/rank-priority` · `GET /platforms/discovery` | 运营/租户看「先打哪几个平台」 |
| 内容矩阵 | `geo_content_matrix_service` | 默认 `rank_first` 选平台；可注入脱敏技术事实 |

### 9.3 公开专利/国标 — 借鉴脱敏（非照搬）

- 用户粘贴 **国家专利公开文本、GB/JGJ 标准摘要** → `public_tech_reference_service` 去掉申请人、专利号、电话，只保留 **参数/标准/性能事实** 写入 GEO 文。
- 写作层：**改写表述**，写「参照公开行业文献」；禁止恢复权利要求原文，避免侵权与机审重复度。
- 这与「抄袭专利」不同：用的是 **公开技术事实** + **脱敏改写**，服务于 Princeton GEO 的 **Statistics Addition** 战术。

### 9.4 下一批 exploration 适配器（按权重）

搜狐号、网易号、企鹅号 → 1688/慧聪 → Alibaba.com / Made-in-China — 每上线 1 家，矩阵 GEO 面 +1，probe 复测验证。
