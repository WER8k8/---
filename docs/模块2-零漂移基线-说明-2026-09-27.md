## 1. 基线语义（务必这样读）

本基线**不是**采集时刻工作区的行为，而是 **`git HEAD` 已提交版本**的 `boq_calculator.py` 行为：

| 字段 | 含义 |
|---|---|
| `result` | **黄金基线** = `git HEAD 90ff513b…` 版本 `BOQCalculator().calculate(params)` 的输出（改动前行为） |
| `result_worktree` | 采集时刻工作区版本输出（在途对照，非基线） |

原因：采集启动时工作区 `boq_calculator.py` **已包含**模块2 的 Profile 注入改动（`git HEAD` 版本 `head_calculator_has_industry_profile_param=false`，工作区 `true`）。
若以工作区为基线，等于把「在途半成品」当成「改动前」，判据将失去意义。
`git HEAD` 不可变，因此该黄金基线**任何时刻都可用 `git show HEAD:backend/app/services/boq_calculator.py` 复现**。

## 2. 采集可靠性

| 项 | 值 |
|---|---|
| git HEAD before / after | `90ff513b81591d335dc08eb1e580b904c1bfa2aa` / 同 |
| git status 前后 | 一致 |
| 3 个关键文件 md5 前后 | 一致（`files_identical=true`） |
| `reliable` | `true` |

采集窗口内代码未变动。**采集结束后** `boq_calculator.py` md5 由 `b8e11b8a…` 变为 `65e8e062…`（白客仍在编辑），故 `result_worktree` 为「中间态」；`result`（HEAD 基线）不受影响。

「可靠性探针」有效性已验证：第二次重跑采集时文件正在被改，脚本自动落 `reliable=false`，并拒绝覆盖可信基线。

确定性验证：两次采集的 593 组 `result`（HEAD 输出）**逐字节 0 差异**。

## 4. 关键发现：在途工作区已存在「非标准材料」零漂移破坏（P0-1）

`_get_base_price` 未知材料回退值被由 `50.0` 改为 `0.0`：

```
# git HEAD（改动前）
return prices.get(material_type, 50.0)

# 工作区（在途，最新版仍为 0.0）
return base.get(material_type, 0.0)
```

实测（593 组中 226 组漂移，**全部**落在不在基价表内的材料：`porcelain`/`铝复合板`/`unknown_material`；5 个已知材料 0 漂移）：

```
params = {"material_type": "porcelain", "quantity_sqm": 100, "incoterms": "FOB"}
HEAD  total = 5000.0  (base_price=50.0)
WT    total = 0.0     (base_price=0.0)
```

`porcelain` **管道可达**：`boq_pipeline_service._material_of()` 对「陶瓷」文案返回 `porcelain`，而计算器基价表无此键 → 报价静默归零，无 error 返回。违反 HS-1（未配置 Profile 时逐字段一致）。
5 个已知材料（marble/granite/ceramic/wood/metal）在途重构**零漂移**，`moq_tiers` 重构（`>=3000/>=1000` 硬编码 → 排序档位）行为等价。
