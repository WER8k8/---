## 一、设计目标（可度量）

| 目标 | 指标（建议 SLO） | 手段 |
|------|------------------|------|
| **首屏快** | 管理端 LCP &lt; 2.5s（内网/预发）；租户站 TTFB &lt; 600ms | 路由懒加载、BFF 聚合、CDN 静态资源 |
| **交互快** | 列表/仪表盘 API P95 &lt; 300ms（热路径） | Redis 缓存、DB 索引、分页上限、并行查询 |
| **功能全** | 现有模块 100% 映射到域；旧 URL **deprecated 不删除** | 三域 + 兼容层 |
| **可商用** | 生产 preflight 绿；Celery/Redis 必启 | 运行时基线 |

## 三、领域划分（功能一张表，不少一项）

| 域 | 包路径（目标） | 现有能力映射 | API 前缀（新/推荐） |
|----|----------------|--------------|---------------------|
| **Core** | `app/domains/core/` | 租户、用户、auth、产品、询盘 unified、订单/报价、支付、物流、IM、referral、client 工作台 | `/api/v1/core/*` 或保持原路径 + tag |
| **Growth** | `app/domains/growth/` | 统一发布、publish_tasks、平台 40、SEO 矩阵、GEO、排名、百度站长、内容、媒体工厂、养号 | `/api/v1/growth/*` |
| **Intelligence** | `app/domains/intelligence/` | UBrain、commercial-os、trade-intel、ai_generate、ai_learning、agent-hub、Accio、super_agent、cognitive、knowledge | `/api/v1/intelligence/*` |
| **Governance** | `app/domains/governance/` | super_admin、founder_ops、ops_jobs、finance 导出、审计、备份、SSL、compliance、system_health | `/api/v1/governance/*` |
| **Public** | `app/domains/public/` | 访客询盘、mobile_public、health、hub | 不变 |
| **Compat** | `app/api/v1/routes/*`（保留） | 全部旧 URL | **原路径 + Deprecation 头** |

**兼容策略**（功能不减）：

- 旧路径 **继续挂载 12 个月**；响应头 `Deprecation: true` + `Link: </api/v1/...>; rel="successor-version"`。
- 新前端 **只调 BFF + canonical API**；旧前端不改也能用。
- `check_mounted_routes.py` 增加 **「兼容路由清单」**，防止误删。

## 四、前端布局（四壳 + 快）

与 [`四壳信息架构与菜单治理.md`](../四壳信息架构与菜单治理.md) **完全一致**，只补 **性能规则**：

| 壳 | 路由 | 首屏策略 | 菜单 |
|----|------|----------|------|
| **Client** | `/client/*` | 只加载 **Dashboard + 当前支柱** chunk | 4 支柱 + 优丁助手浮层 |
| **Ops** | `/dashboard`, `/inquiries`, `/publish/unified`… | 列表页 **虚拟滚动** + 分页 20 | 合并进运营区，不重复 Client |
| **Platform** | `/admin/*` | Tab A/B/C；**实验室默认 Feature Flag 关** | 治理区 |
| **Agent** | `/agent/*` | 独立 bundle，代理登录才下载 | 佣金/开户 |
| **访客** | Nuxt | SSR 关键 CSS；图片 **WebP + lazy** | — |

### 4.1 管理端加载优化（必做）

```text
1. 路由级 code-splitting：每个一级菜单独立 async chunk（Vite dynamic import）
2. 登录后只请求 GET /bff/client/bootstrap（或 platform/agent 对应）
   → 一次返回：用户、租户、菜单、FeatureFlags、未读数
3. 副驾 UBrain：独立 chunk，点击「优丁助手」再加载 copilot.vue
4. 实验室/GEO/RAG：feature_flag=false 时不 import 对应 views
5. 图表 ECharts：onMounted 动态 import，避免进主 bundle
```

### 4.2 BFF 聚合接口（减 RTT，功能通过聚合暴露）

| 端点 | 调用方 | 聚合内容 | 目标耗时 |
|------|--------|----------|----------|
| `GET /bff/client/bootstrap` | Client 壳 | user、tenant、flags、未读询盘数、发布队列摘要、onboarding 步骤 | &lt; 200ms |
| `GET /bff/client/dashboard` | Client 首页 | 四支柱卡片数据（并行 4 查询 + Redis） | &lt; 300ms |
| `GET /bff/platform/overview` | Platform Tab A | 租户数、队列、告警、备份状态 | &lt; 300ms |
| `GET /app/v1/home` | App | **已有**，扩展字段时保持单请求 | &lt; 300ms |
| `GET /bff/agent/summary` | Agent 壳 | 佣金、待开户、团队 | &lt; 200ms |

**规则**：列表详情仍走领域 API；**仅首屏/仪表盘**走 BFF。

## 五、后端性能设计

### 5.1 请求路径分级

| 级别 | 类型 | 处理 | 示例 |
|------|------|------|------|
| **S0** | 热读 | Redis 缓存 30～120s + 单表索引 | 平台列表、dashboard 计数、commercial-os/status |
| **S1** | 热写 | 同步 DB + 失效缓存 | 询盘状态更新、登录 |
| **S2** | 重计算 | **Celery 异步** + 轮询/WS | 跑飞轮、GEO 雷达、批量发布、AI 长生成 |
| **S3** | 外部 IO | 超时 + 熔断 + 降级 Mock 仅 dev | LLM、爬虫、支付回调 |

### 5.2 缓存键规范（Redis）

```text
uj:{tenant_id}:dash:summary          TTL 60s
uj:{tenant_id}:inquiries:unread      TTL 30s
uj:platforms:catalog                 TTL 600s（全局）
uj:{tenant_id}:flywheel:status       TTL 45s
```

写路径在 service 层 **统一 invalidate**，禁止路由里散落删缓存。

### 5.3 数据库

| 项 | 要求 |
|----|------|
| **生产** | 仅 PostgreSQL；连接池 `pool_size=20` `max_overflow=10` |
| **开发** | SQLite 仅本地；`sqlite_paths.py` 解析唯一库文件 |
| **索引** | 询盘 `(tenant_id, status, created_at)`、发布任务 `(tenant_id, state)` 等（Alembic 维护） |
| **读重** | 二期可选只读副本；报表/export 走只读 |

### 5.4 API 层约束（防慢）

- 列表默认 `limit≤50`，最大 100；禁止无分页全表。
- N+1：列表必须用 `joinedload` / 批量查询（领域 service 负责）。
- 大导出：**异步任务** + 下载链接，禁止 HTTP 同步扫全表。
- 中间件链保持，但 **UnifyResponse 仅 /api/v1**，BFF 可返回精简 JSON。

## 六、异步与「功能不少」的长任务

| 能力 | 现状 | 目标 |
|------|------|------|
| 发布队列 | publish_worker | Worker 常驻 + 死信队列 + 管理端只看摘要 |
| GEO beat | celery beat | 预发/生产 **必须** 起 beat |
| 飞轮/AI | 同步易超时 | `POST` → `job_id` → `GET /jobs/{id}` 或 SSE |
| 爬虫 | 外置 Worker | Webhook + 签名；结果写 Core 询盘 |
| 备份 | auto_backup | cron + `backup.last_run` 告警 |

**前端**：长任务统一 **进度条组件**（轮询 2s 或 WebSocket），避免按钮卡死。

## 八、部署拓扑（最小生产集）

```text
                    [CDN]
                      |
                 [Nginx]
          +-----------+-----------+
          |                       |
    [Nuxt SSR]              [Admin 静态]
          |                       |
          +-----------+-----------+
                      |
              [FastAPI x N]  ← 无状态水平扩展
                      |
          +-----------+-----------+
          |           |           |
     [PostgreSQL] [Redis]   [MinIO/R2]
          |
    [Celery Worker x M]
    [Celery Beat x 1]
    [Crawl Worker 外置]
```

| 组件 | 副本 | 备注 |
|------|------|------|
| FastAPI | ≥2 | 健康检查 `/api/v1/health` |
| Celery worker | ≥2 | 发布/AI/GEO 队列可分 queue |
| Beat | 1 | 单点，K8s 用 leader election |
| Redis | 1 主 | 缓存 + broker |
| Postgres | 1 主 | 定期 pg_dump |
