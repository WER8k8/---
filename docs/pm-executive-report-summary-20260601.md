## 一、汇报摘要（Executive Summary）

优丁 **AI-SaaS 智能营销平台 V2.0** 已完成 **工程侧省级门禁**（构建、单测、cert:gate 全绿），但 **产品侧尚未达到「可送省级评测中心现场演示」的标准**。

**核心判断**：

1. **功能多、产品少** — 234 个路由里约 80+ 为 Stub/实验室，租户和评测员仍可能看到，损害「正式 SaaS」认知。  
2. **三壳都糙** — 租户、代理、超管各自为战：emoji 菜单、彩虹 KPI、超管菜单爆炸、代理可跳转超管页面。  
3. **工程与商品脱节** — 12 库开源深读、Vben 换壳方案已就绪，但 **信息架构、送检路径、视觉规范** 未同步落地。  

**PM 建议路径**：不做 234 页大爆炸迁移；**三轨并行 90 天** — ① 送检阻断 S0（1 周）② SaaS 商品化 S1（2–3 周）③ 工程 Wave 1–2（Vben+BFF+kit）。

**North Star（全员一句）**：  
租户登录 30 秒内能回答 — **「我今天该干什么？店运转正常吗？套餐还够用吗？」**

## 三、问题从哪里来（根因）

### 3.1 历史包袱

- 单文件 **234 路由**，四壳混在一个 Admin 里演进。  
- 早期优先 **「功能点位齐」**，未做 **角色隔离 + 菜单治理**。  
- 0 引用 Admin BFF / kit — 菜单硬编码，无法按套餐下发。

### 3.2 三壳各自问题（现网评级）

| 壳 | 用户 | 评级 | 最致命问题 |
|----|------|------|------------|
| **Client 租户** | 付费老板/运营 | D+ | 15 项 emoji 菜单；Dashboard 渐变模板风 |
| **Agent 代理** | L2/L3 | D | 彩虹 KPI；**「查看全平台」链超管** |
| **Platform 超管** | super_admin | F | 侧栏爆炸；层级页 glass hero；实验室外露 |

### 3.3 与外部预期的差距

评测员、租户、抖音/B 端审美教育过的用户，期望的是：**Linear/飞书式克制、任务导向、≤5 项导航、无半成品菜单**。  
现网像 **2018 功能堆砌后台 + 个人 emoji 笔记** — 用户原话：「不敢送省级鉴定中心」。

### 3.4 工程绿 ≠ 产品可送检

| 工程已达标 | 产品仍缺 |
|------------|----------|
| API 接真、Math.random=0 | 送检 **鉴定面** 路径清晰 |
| 导航无 dead link | **角色零泄漏**（代理不见超管） |
| 构建可发布 | **30 秒第一印象**、12 张截图专业 |

## 五、产品战略（不变）

### 5.1 目标（OKR）

**O**：租户与内部团队认为「这是正经 SaaS，不是内部工具」。

| KR | 90 天目标 |
|----|-----------|
| KR1 | 7 日内 onboarding 核心 3 步 ≥50% |
| KR2 | Client 一级菜单 ≤5，3 次点击到主任务 |
| KR3 | 「找不到功能」工单 ↓30% |
| KR4 | Dashboard LCP <2.5s |

### 5.2 不做什么

- 234 路由全量迁 Vben  
- 换 Java/RuoYi 后端  
- 实验室对租户/送检默认可见  
- 第二 UI 库整库并进  
- 送检前重做全部超管页  

### 5.3 技术定案（PM 认可，不重复争论）

- 唯一 Admin 壳：**Vben 5 web-antd**  
- 抽取：**youding-admin-kit**（Art 表格 + Soybean API）  
- 后端：**FastAPI 不动**；契约 **Admin BFF**  
- 复杂表单：**Formily 1 页试点**（W3）  
- 对外：**daisyUI + HTMLrev**（marketing，W3+）

## 六、三壳目标形态（PM 定稿）

### 6.1 租户 Client — 「今日经营」

**一级菜单（4）**：工作台 · 获客 · 发品 · 账户  
**+1**：财旺助手（悬浮，非菜单）

**Dashboard**：Bento 六格 — Onboarding / 未读询盘 / 发布中 / 今日待办 / 套餐续费  
**Hide**：视频工厂、出口 IP、AI 场景等（Lab 或 Plan Gate）

### 6.2 代理 Agent — 「业绩与开户」

**一级（5）**：首页 · 客户 · 开户 · 佣金 · 预警  
**L2/L3 差异**：省代有下级汇总，市代无  
**永久禁止**：任何 `/admin/*` 入口  
**视觉**：白底 KPI + 左色条，**禁止彩虹渐变**

### 6.3 超管 Platform — 「运营 | 商业 | 治理」

**主路径 ≤12**；实验室 **Feature Flag 关**，抽屉 +「非送检范围」水印  
**层级页**：删 hero-glass → 标准树表 + 详情  
**送检**：只走 **「鉴定面」** 专用路径（见 §八）

## 十二、PM 结论与请求

### 结论

1. 产品 **不应** 在现网面貌下送省级现场；工程绿只解决「能跑」，不解决「像商品」。  
2. **最优路径** 已明确：S0 阻断 → W1/W2 商品化+工程并行 → S2 送检包；**不是** 等 Vben 全迁完再改产品。  
3. 租户 **P0**，代理/超管按 **送检鉴定面** 精修，不全员重写 200 页。  

### 请求 Owner

1. **批准 S0 七项** 立即开发（预估 1 周，可与 Vben fork 并行）。  
2. **确认送检窗口** 与是否接受「鉴定面 + 实验室声明」策略。  
3. **本周书面答复** Brand Tier / Trial，解锁 Login 与 Plan Gate 设计。  
4. **指定 PM 签字权** 完成 L3 六项与手册定稿节点。
