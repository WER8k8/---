## 4. 已知风险与改进建议

### 高风险

1. **速率限制存储**: 当前限流使用内存字典 (`SlidingWindowRateLimiter._windows`)，多进程部署时各进程独立计数，无法达到预期限流效果。
   - **建议**: 生产环境替换为 Redis 实现 (`redis-py` + sorted set 滑动窗口)

2. **JWT Token 无法主动失效**: 当前 refresh token 黑名单使用内存存储（`refresh_token_blacklist.py`），重启后失效。
   - **建议**: 生产环境使用 Redis 存储黑名单，或使用短期 access_token + 数据库 blacklist

### 中风险

3. **日志敏感信息泄露**: 日志可能包含 token、密码等敏感字段。
   - **建议**: 添加日志脱敏中间件，自动遮蔽 password/token/secret 等字段

4. **文件上传验证**: 当前文件扩展名白名单 (`ALLOWED_EXTENSIONS`)，但未验证 MIME 类型。
   - **建议**: 结合 `python-magic` 验证文件真实类型，拒绝伪装扩展名

5. **CORS 预检缓存**: `allow_methods=["*"]` 和 `allow_headers=["*"]` 过于宽松。
   - **建议**: 限制为实际使用的 Methods 和 Headers

### 低风险

6. **HTTP 方法限制**: 部分公开接口无需支持 PUT/DELETE。
   - **建议**: 为公开接口显式限制允许的 HTTP 方法

7. **会话固定**: SessionMiddleware 使用 `SECRET_KEY` 签名，但未实现登录后 Session ID 重新生成。
   - **建议**: 登录成功后调用 `request.session.clear()` + 重新签发

## 6. 审计结论

**总体安全评级: B+ (良好)**

系统已实施多层安全防护：
- 输入验证层 (Pydantic + SecurityMiddleware)
- 认证授权层 (JWT + 角色权限 + 租户隔离)
- 响应安全层 (CSP + HSTS + 安全头)
- 限流防护层 (分层限流 + 防暴力破解)
- 监控审计层 (Sentry + 日志 + 性能追踪)

**重点改进方向**:
1. 限流和 Token 黑名单迁移至 Redis
2. 日志脱敏
3. 文件上传 MIME 验证
4. CORS 策略收窄
