## 3.5 凭证真源：要哪些字段、去哪儿申请、填到哪儿

运营侧问「凭证上哪里找」，答案是三层落点 + 一个机器可读清单，不要再靠人记忆：

- **清单真源**：`backend/app/services/platform_credential_guide.py`
  - `PLATFORM_CREDENTIAL_REQUIREMENTS`：每个平台的**必填字段组**（组内任一满足即可，组间都要满足）；
    被 B2B 适配器与账号 API 共用，改门禁只改这里。
  - `GUIDES`：逐平台的申请入口 URL + 操作步骤 + 注意事项（含风控/资质限制等如实提醒）。
  - `env_credential_status()`：环境变量类凭证的配置状态，**只回布尔，绝不回值本身**。
- **对外接口**：`GET /api/v1/seo-matrix/platform-credential-guide`
  回 `guides`（完整指引）+ `env_status`（布尔）+ `storage_note`（填哪儿的说明），响应内无任何密钥值。
- **填写落点**（优先级 `configs` < `cookie_data` < `token_data`）：
  1. **平台账号**（单店专属凭证、国内 Cookie）：`POST/PUT /api/v1/seo-matrix/platform-accounts`。
     `PUT` 支持把指引字段平铺传入（如 `{"alibaba_member_id": "..."}`），服务端按字段类型路由到
     `cookie_data` / `token_data` / `configs`；`GET /platform-accounts` 每条回 `credential_status`
     （含 `masked` 掩码与 `missing_fields`），用于判断「还差哪个字段」。
  2. **全局通道级密钥**：`backend/.env`（模板见 `.env.example` / `.env.prod.example` 的「平台凭证」段）。
     例：`GSC_SERVICE_ACCOUNT_JSON`、`BAIDU_SITE_TOKEN`、`AITOEARN_API_KEY`。
  3. **`platform_configs` 键值表**：上面两条的持久化兜底，账号无覆盖时回落到此。
- **诚实口径不变**：缺凭证 → `PLATFORM_NOT_CONFIGURED`；无实现 → `PLATFORM_NOT_IMPLEMENTED`；
  dev mock 必带 `mode=mock`。三家海外 B2B 均需付费商家账号 + 接口权限，没权限时链路如实停住。

## 5. 不变量（全阶段硬锁）

- 内核降级即显式 `incomplete`，禁止用占位值/默认值冒充已就绪。
- 认证/资质只透传内核 evidence，无则不写，不编造。
- 动 `content_masters` 必须走 Alembic 单 head，不裸改表结构。
- 任何接线改完跑 `pytest`（本层单测）+ 相关 `publish_tasks` 回归。
- 内核快照只在真组出内核时写入：组不出（无标题）不写假值；降级内核如实带
  `schema_ready:false` + `completeness` 落库，供运维回溯「当时缺哪些硬事实」。
