# 蜂群 P6 商业闭环（2026-05-31）

## 设计原则

- **审计与业务解耦**：写 audit 失败只打日志，不阻断改派
- **证书按需拉取**：不后台轮询；验签失败时刷新缓存重试一次
- **E2E 边界**：默认 in-process，不依赖 ngrok/后端进程；`production` 拒绝执行

## 范围

| 编号 | 能力 | 状态 |
|------|------|------|
| W21 | 询盘改派结构化审计 + 历史 API + 后台展示 | ✅ |
| W22 | 微信平台证书 serial 缓存与验签轮换 | ✅ |
| W23 | 支付宝沙箱 E2E 脚本（in-process / 可选 HTTP） | ✅ |

## W21 改派审计

**服务** `inquiry_assignment_audit_service.py`

| action | 含义 |
|--------|------|
| `inquiry.assign` | 管理员手动改派 |
| `inquiry.auto_assign` | 落地页自动分配 |

**API** `GET /inquiries/{id}/assignment-history`

- 管理员/超管/租户管理员：全部
- 销售：仅本人负责询盘

**前端** 展开行懒加载「负责人变更记录」

## W22 微信证书

**服务** `wechat_platform_cert_service.py`

1. 优先 `WECHAT_PAY_PLATFORM_PUBLIC_KEY`（可配 `WECHAT_PAY_PLATFORM_SERIAL`）
2. 按 `Wechatpay-Serial` 查内存缓存
3. 缺失时 GET `/v3/certificates` 解密并缓存（TTL=`WECHAT_CERT_CACHE_TTL_SECONDS`）
4. `verify_v3_notify` 失败时 `force_refresh` 重试一次

## W23 支付宝 E2E

```powershell
cd backend
# 默认：进程内验单（无需启动后端）
python scripts/alipay_sandbox_e2e.py

# 集成：需 backend 已监听 8001
python scripts/alipay_sandbox_e2e.py --http --base-url http://127.0.0.1:8001

# 仅输出 ngrok notify 建议地址
python scripts/alipay_sandbox_e2e.py --public-url https://xxxx.ngrok-free.app
```
