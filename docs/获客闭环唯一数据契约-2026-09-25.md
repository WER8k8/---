## 0 · 目标与范围

### 【目标】
把当前**至少 8 套彼此无晋级关系的获客对象**收敛为**一条唯一晋级链 + 唯一主档归属 + 单一口径状态枚举**，使「外部线索 → 询盘 → 商机 → 订单」每一段都有确定的触发条件、负责服务、落库表和状态值，并可用真实业务数据端到端验证。

### 【范围】
- **包含**：
  1. 核心实体主档归属与收敛路径（8 套对象 → 唯一主档）。
  2. 唯一晋级链 7 段的触发条件 / 负责服务:函数 / 落库表 / 状态枚举。
  3. 状态枚举统一（`LeadStatus`、CRM stage、邮件状态机、四态标记）。
  4. 8 个确定性 P0 断点的逐条修复方案与可验证验收标准。
  5. DSH/Hermes 双平面路由口径。
  6. W1~W4 子任务清单与需 Alembic 的库表变更。
- **不包含（显式不做，避免后期扯皮）**：
  - 不改任何生产代码（W0 阶段只产出设计）。
  - 不做前端页面改造与视觉调整。
  - 不接入新的外部 SaaS / 不申请新 Key / 不碰 `40+` 平台真实外发。
  - 不删除任何既有模型或路由文件（收敛方案给出，实施在 W2/W3）。
  - 不做性能优化与缓存重构。

### 【一句话收敛原则】
> **一个来源只经由一个 Adapter；一条线索只有一个主档（`prospect_leads`）；一次询盘只有一个主档（`inquiries`）；一次商机只有一个阶段词表（`crm_pipeline.STAGE_ORDER`）。**

## 4 · DSH / Hermes 双平面路由口径（固定）

采用**双平面**（**否决**"每单必经 DSH"）：

| 请求类型 | 平面 | 处理路径 | 证据/约束 |
|---|---|---|---|
| 普通 CRUD（查列表 / 改字段 / 看会话） | **UJ API 同步** | 直接走 FastAPI 路由（如 `/lead-generation/*`、`/crm/pipeline/*`） | 不走 DSH、不排 Hermes 任务 |
| 一键找客 / 批量触达 / 生成 PI | **Hermes 任务** | `hermes_task_bridge.ROUTERS`（`services/tasks/hermes_task_bridge.py:531`）→ 执行器（Accio / DeerFlow / TradeAI / GoodJob） | 任务包五字段铁律：`tenant_id/idempotency_key/lease_ttl/checkpoint/budget`（`orchestration/interfaces.py:41-50`） |
| 模糊自然语言需求 | **DSH → Hermes** | `/deepseek-harness` → 意图识别 → 派 Hermes 任务 | DSH 只做意图拆解，调度主权在 Hermes（`interfaces.py:17`） |
| 外部平台发送（邮件外发 / WhatsApp / 社媒） | **必须人审 + 凭据 + 证据** | 首封人审闸（`email_outreach_service.list_pending_review_outreach`）+ 证据 `evidence_url` | 无 Key 显式降级，禁止静默假成功 |

- A2：`prospect_leads` 物理表与模型一致（含 `score_match/score_email/score_evidence/score_contact`、`provenance_metadata` 等）；**W1 须用 `tools/db_probe.py` 实查复核**（若漂移，走 Alembic，不手工改）。

### 风险
- R1（高）：**P0-3/P0-6 的"断点"定性被本契约修正为"未挂载死代码"**。若主理人按原清单"修复"该文件，会得到"改完仍 404"的结果。**建议先按 §7 决策收敛方式再派工**。
