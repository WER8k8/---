# 管理端路由与功能映射表（对照 `4-API接口定义.md`）

> **用途**：与汇总进度/验收一致——**领取任务**（在表中定位功能）→ **分配**（打开对应路由）→ **验收**（核对 API 章节与页面主按钮是否可达）。  
> **Base**：前端路径均为站点根下路径（如 `/news`）；后端为 `/api/v1/...`。

## 8. 智能调度师 / 蜂群 / 自动滚动领任务（已落地）

### 8.1 权威数据源（给 Cursor 子代理、CI、外部调度器）

- **JSON 任务队列**：[`admin-route-task-board.json`](./admin-route-task-board.json)  
  - 每条含：`id`、`title`、`route`、`api_sections`、`api_prefixes`、`sidebar_group`、`priority`、`acceptance[]`、`owner_pool`  
  - **`priority` 越小越优先**（滚动领任务时按升序取队首）。

### 8.2 人类仍读本文档 §2–§6；机器只读 JSON

避免双处手写漂移：**改路由或增页面时，先改 JSON**，再同步本 Markdown 表格。

### 8.3 命令行（仓库根目录）

| 命令 | 作用 |
|------|------|
| `npm run task-board:validate` | 校验 JSON 结构、唯一 id |
| `npm run task-board:roll` | 按 priority 输出待领队列（JSON） |
| `npm run task-board:next` | 输出下一条任务（priority 最小） |
| `npm run task-board:list` | 打印全部任务；加 `-- --pool=frontend` 可过滤 |
| `npm run task-board:auto` | **全自动开始**：校验 → 锁定队首 → 写入 `docs/.task-board/active-task.json` → 后台启动 `frontend/admin` 的 `npm run dev` |
| `npm run task-board:auto:no-dev` | 同上但不启动 Vite |

直接调用：`node scripts/admin-task-board.mjs validate|list|next|roll`；全自动：`node scripts/task-board-auto-start.mjs [--no-dev]`

### 8.4 Cursor 规则

见 [`.cursor/rules/admin-task-board.mdc`](../.cursor/rules/admin-task-board.mdc)：多会话/子代理统一从 **同一 JSON** 领任务与写验收说明。

### 8.5 单任务验收模板（可复制到 PR）

```text
Task-ID: <id>
Route: <route>
API §: <api_sections>
Acceptance: 已逐项对照 admin-route-task-board.json 中 acceptance 数组
```
